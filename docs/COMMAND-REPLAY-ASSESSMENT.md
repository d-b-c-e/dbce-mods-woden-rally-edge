## Exact candidate behavior and recording gaps

The optional adapter reads its injected `_outputClock` once per eligible `TryProcess`, checks finite/nonnegative time and valid cap/input, and creates the shared mixer with current cap, slew1.5/s and **headroom0**. The first timestamp and every cap change prime zero without an invented interval. Subsequent calls use the previous adapter end and current read; duplicate/rewound/stale/nonfinite intervals reject, reset adapter state and cause the caller to stop output. The shared accepted interval limit is50ms with its existing1e-9 interval/adjacency tolerances. No Trigger/collision route is active. These are inspected source facts, not new timing measurements or adopted settings.

| Needed for command recomputation | Present evidence | Gap |

| Exact clock read actually used by adapter | Candidate has clock seam; recorded comparison feeds `row.ElapsedSeconds` | No captured per-invocation clock/epoch; elapsed-time comparison is an injected scenario |

Some force operations happen outside sampled car rows: preparation/reacquisition zero, suspension, panic, close and terminal shutdown. Cumulative attempt counters and a model reset epoch cannot reconstruct their exact order. An output-clock datum from a gated car row must not be invented if the adapter was never called. A rejected/nonfinite clock is part of the actual input and cannot silently be replaced with a valid sample timestamp.

## Minimal versioned proposal

[COMMAND-REPLAY-PROVENANCE-PROPOSAL.json](COMMAND-REPLAY-PROVENANCE-PROPOSAL.json) defines proposed `dbce.woden.cadence-command-observation@1` capture requirements. It is an engineering proposal, not an adopted product/recording schema, installed optimizer discovery or a playable recording. It separates five necessary parts: immutable build/case identity, exact adapter clock, hashed active settings/budget revisions, ordered model/cadence resets and semantic gates, and distinct produced/attempted/accepted output-call observations.

Clock origin explicitly distinguishes injected recorded elapsed from an observed runtime-stopwatch read **at the adapter**. Exact IEEE754 bits preserve the double actually used, including rejected NaN/infinity; a rounded tick cannot silently replace it at an interval tolerance boundary. Model/cadence epochs are distinct. Cap changes record new mixer creation and zero priming. Command values use binary32 identity for exact production float comparisons. Native nominal integers/submission timestamps are only populated if actually observed; missing is unavailable, not0. Managed call timing remains separate from native effect/driver timing and physical torque.

There is no justified command analyzer/replayer implementation against current captures: required clock/reset/call inputs are absent. A parser alone would label completeness without independently reproducing command state, while reusing elapsed time would only repeat the existing scenario. The smallest next implementation milestone requires an independently reviewed, source-only observer at the actual adapter/controller seams, then a pure fake-device fixture that compiles the exact production adapter and shared sidecar, preserving the older input DLL. Original data would remain immutable; new observations require exclusive `CreateNew` output. This observer is not implemented or authorized for a Unity launch here.

Before any such port, reconcile `11f780a` with current `95d1ff7` callback drain, lifecycle lock, terminal producer rejection, explicit restart and zero-before-close. The older candidate lacks those reviewed lifecycle protections; blindly applying it would lose the current foundation. Preserve current model math, user settings/caps/gains, HAT39 and all native/shared-owner work. Collision remains unavailable; no event reserve or physical equivalence is inferred from candidate arithmetic.

Future conformance scope is limited to real clock priming/cap change, separate reset epochs, gate suppression, clock rejection with zero, failed-write attempted-versus-accepted distinction, out-of-band shutdown calls, incomplete/identity-mismatched trace refusal and atomic artifact ownership. Existing preview replay and request-reference datasets are preserved. No builds of runtime/cadence, devices, Unity, screen use, package modification or publication occur in this assessment; independent review precedes any implementation/adoption.
