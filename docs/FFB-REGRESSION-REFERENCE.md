# Offline FFB regression reference v1

This source-only fixture observes the actual production `ForceController` compiled into the existing regression harness, its production `ForceSignal` model 3 and the exact retained `Dbce.Wheel.Ffb` shaper binary. Only test context settings allow injected `ForceOptions`; production settings, gain, cap, model math, native ABI and package/runtime are unchanged. The fake output device always accepts software writes and records zero/close order. It never loads DirectInput or opens a wheel.

The versioned reference is `components/wheel/tests/WodenRallyEdge.Tests/Fixtures/ffb-reference-v1.json`, schema `dbce.woden.ffb-regression-summary@1`. Each of 20 rows covers 300 samples at an injected 20 ms interval (6 seconds), strengths 0/25/50/100 percent, fixed peak 25 percent and otherwise unchanged model defaults. Reference contact channels contain speed 20 m/s, forward velocity 20 m/s, front contact force 3000 per wheel, grounded front wheels and zero steering. Contact-force units are provisional model inputs, not calibrated rig measurements. Inputs are steady slip 1, slip 0.6*sin(2*pi*t), slip 0.6*sin(8*pi*t), sign step at 3 seconds and steady slip with lifecycle gates. Input hashes include the complete input channel dictionary, timeline and injected gate context.

Lifecycle gates are pause samples 50..59, lost focus 70..79, lost camera ownership 90..99, explicit respawn discontinuity sample110 and explicit stale-source discontinuity130. Stale-source is a structural flag, not measured transport latency. Each reference runs independently, repeats exactly and checks its sign-mirrored envelope. The baseline checks all metrics, input/command hashes, options and evidence boundaries. Adjacent strength comparisons report differences; they do not assume increasing strength must increase RMS in dynamically slew-limited oscillation. Every sample checks the unchanged output cap and recorded tuning/sent channels. Every run checks shutdown zero-before-close, zero `Sent`, disconnected ownership, terminal producer rejection and no saved-preference changes.

Metrics distinguish normalized command minimum/maximum/peak/RMS/absolute impulse; samples at the output cap; **unconditioned model demand above that cap**; nonzero command duty; fake accepted write counts per injected second; observed sign-change cadence; observed finite-difference slew. Cap occupancy uses `abs(command) >= 0.25 - 0.000001`; nonzero duty uses strict `abs(command) > 0.0015`. Sign changes compare successive above-threshold commands, retaining the last nonzero sign across intervening zero/below-threshold intervals; they are not adjacent-sample crossings or native effect events. Slew is the maximum `abs(currentSent - previousSent)/0.02` within the 300-sample envelope, starting with previousSent=0, including in-envelope gate zeros and excluding the later shutdown zero. Demand exceedance is not an internal hard-clipping counter: nonlinear saturation, smoothing, ramp, deadband and slew conditioning can prevent the cap being reached. Immediate gate zero can exceed a nominal slew rate and is not classified as a limiter violation. Shutdown is outside the six-second envelope and is reported separately. Request duty/cadence is not native effect duration, scheduling, watchdog timing or actual driver delivery. Native periodic/condition effect duty and cadence are unavailable in this constant-force consumer fixture.

Collision is explicitly unavailable: no verified production collision producer exists, and no collision waveform is fabricated. MOZA R12 is historical identity only; gain/calibration and measured torque remain unknown. No physical Nm, perceived-force equivalence across games, installed tuning recommendation or user50%-strength equivalence is claimed. Historical recordings/settings are not read or changed by this reference.

Existing coverage is retained rather than replaced:

- `ForceEnvelopeFixtures` keeps its nine signed generic shaper pulse pairs (10836 checks). Those are synthetic conditioning probes, not game collision events, and retain their original evidence identity.
- `RecordedForceReplay` and existing synthetic recording/controller replay tests still enforce original capture/config/profile/case hashes and ordered model validity/reset/gates. Structural preview reprocessing does not reconstruct native cadence or delivered force. Real private captures and original observations are untouched.
- The separate reviewed opt-in cadence candidate11f780a55c15c91aa7403c80de3352f68446fbfb is outside canonical baeb286 and is not merged, activated, copied or packaged here. Its guarded output-clock/zero-priming fixtures and immutable recorded comparison remain separately attributed. No shared-toolkit project, owner WIP or dependency ABI changes.

Run the existing harness to compare the immutable checked-in reference. To create a new exclusive local summary with comparison:

```powershell
dotnet run --project components/wheel/tests/WodenRallyEdge.Tests -c Release -- --ffb-summary <new-summary.json> components/wheel/tests/WodenRallyEdge.Tests/Fixtures/ffb-reference-v1.json
```

Output uses atomic `FileMode.CreateNew` after generation/comparison and refuses both pre-existing artifacts and another writer's concurrent creation. The advisory existence precheck is not the ownership guarantee. The ordinary harness deterministically rendezvous with a separate task inside generation, creates a binary sentinel artifact, and checks IOException refusal plus exact byte/hash preservation. A deliberately changed reference is rejected. Changing model behavior requires a separately reviewed, newly versioned reference; do not overwrite previous datasets to make tests pass. Exact build/source/test hashes and emitted artifacts are external review evidence. The normal source verification script also runs this reference through the existing harness. Publication awaits independent review; physical/runtime acceptance remains separately coordinated.
Reference generation and exact-hash comparison are validated on Windows x64/.NET10 with the pinned shared assembly. Portability across runtime/architecture is not assumed; changed floating-point traces require investigation and separately versioned evidence.
