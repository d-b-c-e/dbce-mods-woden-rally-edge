The wrapper pins the original owner `d8df97b` receipt SHA-256 `F645FE98...B5EF6B5`, its 14 owned payloads and the actual plugin file set before mutation. It uses `Save-ControlFiles` for the complete plugin subtree, receipt, config/save, BepInEx core, bundled dotnet loader, loader entry files and log, plus a raw Unity preference snapshot. Under one shared lease it installs the new 17-file private candidate, runs the existing applied-car trial with the load-muted native overlay, and uses `Restore-ControlFiles` to remove the three candidate-only plugin files and restore the original 14, receipt and owner state. If the game remains open or restoration cannot be verified, the wrapper retains the lease for recovery. A failed/incomplete trial still restores owner state. No launch is authorized by this document alone.

Success requires the existing trial and restoration verdicts, three measured native plateaus, and `ForceCaptureCoverage` showing at least two cumulative grounded forward seconds at 15 km/h or more, `Driving` front-load reference, at least one valid analysis row, gate 1 and zero native sends, connections or delivery attempts. Afterward, run the existing `TelemetryInspector reprocess` and `ffb-analysis-export` on a **copy** of the archived `source.jsonl`, `force-config.json` and `capture-profile.json`; keep their original hashes unchanged. The offline export must report more than zero normalization-eligible rows. A stalled car, scenery hit, source drop, incomplete recorder, owner-state mismatch or absent eligible rows is a failed/incomplete observation for diagnosis, not a reason for blind repeat. This synthetic straight-throttle capture establishes producer/reference eligibility only; it does not validate normalization, physical torque or owner feel.
