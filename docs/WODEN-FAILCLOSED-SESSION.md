## Resulting behavior

1. Cold admission validates the existing artifact/configuration tuple, latches
   managed output refusal and installs the passive transport gates. The consumer
   remains **UNARMED**. Its fresh `game-focus.json` receipt is available without
   admitting menu transitions, native observation reader timing or raw pulses.
   The qualified no-force native build retains its existing load-time safety
   latch; that safety state alone is never consumer workload admission.
2. Steam adoption retains PID, native creation ticks and executable. It does not
   request activation. The shared selector waits for the visible Unity client
   with an independent90s render budget. No title/largest-window heuristic.
3. At RenderReady, the shared Activate callback atomically publishes one local
   `foreground-request.json`, binding PID/birth/image/HWND/class and a fresh45s
   deadline. The parent sends at most one request for the supported Sky provider
   activation when needed. There is no owner-idle gate, direct PowerShell
   foreground call, backend substitution, input retry or automatic rerun.
4. Exact native HWND/PID/birth/image/class and a fresh (<=1000ms) game-focused
   receipt precede the5s arm budget. `command.json` carries the cold nonce,
   sequence1, operation `arm` and exact selected client. The actual in-process
   probe rechecks its own identity, native foreground, window class/visibility
   and game focus before native enable and replies with that nonce/sequence.
   A provider return or sent/read message alone cannot arm it.
5. Every observation row and every positive raw command rechecks terminal
   revocation, expiry and native/game focus. Native startup menu transitions are
   gated too. The existing schema10/11/12 recipes and vehicle/force code remain
   unchanged. This is no evidence for the no-drive or physical feel complaint.
6. Abort first publishes `<positive-probe>/revoke.json` independently of the
   sequence mailbox. The probe checks it before commands and pulses. Revocation
   is terminal, including a late pending arm. It closes the existing readers,
   confirms resident `no sample running` and publishes identity/nonce-bound
   `stop-ack.json` with strict `revoked`/`probeNeutral` booleans. An incomplete
   Native observation reuses its existing Finish -> recorder Stop ->8s normal
   Quit path; no kill, injected escape or physics write is added.
7. Shared Stopping also invokes the installed companion's existing exact
   `-Stop -RequestId` entry and removes only the matching one-shot request.
   Every stop action is attempted even when another fails. An already Completed
   exact recording may refuse a redundant Stop; companion exit and all process
   identities are still independently required. ExternalLaunch cannot relaunch
   Woden itself. The companion bootstrap protects its own redirected standard
   handles before it starts descendants, using the pinned shared helper.
8. Independent60s stop and absolute120s quiescence budgets require probe-neutral,
   companion-exited and launch-request-absent receipts, then the complete retained
   identity census. Restore executes only after these gates. Canonical verified
   later-birth `Reused` means the original is absent; the replacement is never
   adopted, stopped or killed. Missing/ambiguous birth data retains custody.
   Pre-session failures revoke and remove requests independently; an unknown
   launch or missing neutral acknowledgment remains cleanup-pending. A failure
   before any launch/companion may restore only after a safe complete census.

The callback adapter is `tools/controls/WodenGameSession.ps1`; generic sequencing
and native witness interpretation remain in the shared toolkit. Callback
operations are bounded by their passed elapsed deadline. The existing recorder
startup/collection deadlines remain active; cleanup has its own budget.
