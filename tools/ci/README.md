# Local-first asset-free source checks

Run `pwsh -File tools/ci/Verify-AssetFree.ps1` locally with the exact .NET SDK in global.json installed. Local checks are the default route; GitHub Actions is an optional manual-only check and is not a prerequisite for locally preparing a release. No NuGet package feeds are used: NuGet.Config clears sources and the two projects require only SDK reference packs and the repository's existing managed libraries. The unchanged runner verifies FFB/Telemetry/Recording DLL pins and the four byte-pinned generic delivery contract files before building.

The existing Verify-Source.ps1 remains the full local source validation route. Its plugin/solution and UI tests require ignored BepInEx, generated game interop and proprietary game references. The existing installer tests also copy the actual GameAssembly.dll and need an external loader archive. Those dependencies are deliberately excluded here; no download/import/stub replacement of proprietary assemblies is attempted.

Both projects compile source directly into net10.0 with warnings as errors; production targets/net6 binaries are unchanged. This is reproducible source-level subset coverage under the pinned SDK, not proof that the full solution or shipped binaries build/behave identically. Shared fixture fields used only by excluded timer/game tests are explicitly initialized in the CI entrypoint instead of suppressing compiler warnings. The generated golden observations use the existing pinned shared ForceShaper and must match the existing reference; no gain/cap or model changes.

All ZIP entries, metadata source IDs and unsupported GameAssembly.dll content in setup checks are explicitly **inert synthetic fixtures**, not game assets or release artifacts. They are created only in unique disposable temporary directories. No setup entrypoint in metadata is executed. Only actual installer refusal gates run, with explicit synthetic paths and no production hash bypass. Existing owner settings, games and archives are never read or modified. Normal test output and disposable synthetic files are not uploaded or released. The fixed CLI child has a 45-second deadline; only that owned child can be terminated on timeout.

Workflow policy: **workflow_dispatch only**; push and pull_request triggers are absent. Once this policy is present on main, ordinary branch/main pushes and PR events do not schedule this workflow. An explicit hosted dispatch still consumes runner allowance and requires coordinator direction; no dispatch or billing change is implied by local validation. Windows2025 runner, 15-minute job deadline and contents:read only remain unchanged (all unspecified token permissions none). There are no configured secrets, caches, services, environments, package/release/artifact uploads or deployments. Checkout credentials are not persisted. Only official actions are used, pinned to full immutable commits verified from their official release refs: checkout v7.0.1 `3d3c42e5aac5ba805825da76410c181273ba90b1`, setup-dotnet v6.0.0 `a98b56852c35b8e3190ac28c8c2271da59106c68`. SDK10.0.401 has rollForward disabled. GitHub supplies its normal read-only checkout token; no user-configured secret is required. No untrusted title/body is interpolated into a shell command.

The reviewed runner baseline passed 36,804 managed subset assertions, 22 geometry assertions, 18 fixed-CLI subprocess checks and 17 metadata/ZIP/setup-refusal checks with zero-warning builds, both locally and in earlier hosted runs. A new local receipt must identify its own exact commit/tree, clean or explicitly cataloged source state, SDK version, command, exit status, assertion counts and SHA256 of retained logs. Preserve the receipt and logs privately outside package/source payloads; the runner itself prints results and does not generate a release attestation. A local pass qualifies only the source subset above. It is neither a new hosted result nor certification of full solution builds or release binaries.

For a local release, independently bind the runtime, native, dependency, installer and packaging revisions to the exact produced files and archive checksum. Run applicable full-source and exact-package integrity, installer/rollback/preservation checks locally with authorized dependencies; review privacy/license/allowlist and provenance before any separately authorized artifact upload. Only an approved private destination and exact reviewed artifact may be uploaded. Do not bundle proprietary game/loader/interop assemblies, owner settings or recordings. Do not rebuild or relabel the existing frozen shutdown archive merely because newer source checks pass. [Delivery status and provenance](../../docs/DELIVERY.md) distinguish private published source, the unpublished frozen 0.2.14-shutdown.1 candidate and installed 0.2.12. Source/package review, release readiness, coordinated closed-game installation and attended rig/visual acceptance remain separate gates.
