# Proposed asset-free hosted checks

This is an isolated source candidate, not an enabled or dispatched hosted workflow. Run `pwsh -File tools/ci/Verify-AssetFree.ps1` with the exact .NET SDK in global.json installed. No NuGet package feeds are used: NuGet.Config clears sources and the two projects require only SDK reference packs and the repository's existing managed libraries. The script verifies unchanged FFB/Telemetry/Recording DLL pins and the four byte-pinned generic delivery contract files before building.

The existing Verify-Source.ps1 remains the full local source validation route. Its plugin/solution and UI tests require ignored BepInEx, generated game interop and proprietary game references. The existing installer tests also copy the actual GameAssembly.dll and need an external loader archive. Those dependencies are deliberately excluded here; no download/import/stub replacement of proprietary assemblies is attempted.

Both projects compile source directly into net10.0 with warnings as errors; production targets/net6 binaries are unchanged. This is reproducible source-level subset coverage under the pinned SDK, not proof that the full solution or shipped binaries build/behave identically. Shared fixture fields used only by excluded timer/game tests are explicitly initialized in the CI entrypoint instead of suppressing compiler warnings. The generated golden observations use the existing pinned shared ForceShaper and must match the existing reference; no gain/cap or model changes.

All ZIP entries, metadata source IDs and unsupported GameAssembly.dll content in setup checks are explicitly **inert synthetic fixtures**, not game assets or release artifacts. They are created only in unique disposable temporary directories. No setup entrypoint in metadata is executed. Only actual installer refusal gates run, with explicit synthetic paths and no production hash bypass. Existing owner settings, games and archives are never read or modified. Normal test output and disposable synthetic files are not uploaded or released. The fixed CLI child has a 45-second deadline; only that owned child can be terminated on timeout.

Workflow policy: Windows2025 hosted runner; 15-minute job deadline; contents:read only (all unspecified token permissions none); no configured secrets, caches, services, environments, package/release/artifact uploads or deployments. Checkout credentials are not persisted. Only official actions are used, pinned to full immutable commits verified from their official release refs: checkout v7.0.1 `3d3c42e5aac5ba805825da76410c181273ba90b1`, setup-dotnet v6.0.0 `a98b56852c35b8e3190ac28c8c2271da59106c68`. SDK10.0.401 has rollForward disabled. GitHub supplies its normal read-only checkout token; no user-configured secret is required. Pull requests use pull_request, never pull_request_target; no untrusted title/body is interpolated into a shell command. Push/PR main and manual dispatch are defined, but no workflow push or dispatch is authorized by this candidate.

Local validation of the exact scripts passed: 36,804 managed subset assertions, 22 geometry assertions, 18 fixed-CLI subprocess checks and 17 metadata/ZIP/setup-refusal checks; zero-warning builds. This is not hosted CI success. Workflow YAML was reviewed as source; no hosted runner or GitHub workflow-schema evaluation was invoked. The first compiler attempt correctly rejected three unused fake fields; explicit initialization fixed them. A setup assertion initially expected the wrong symbolic-link diagnostic, then was corrected to the actual bounded refusal. Full local suite/private dependency validation, actual package/install acceptance, hardware and display acceptance remain separate gates.
